# 外置窗口鼠标输入修复与验收计划

## 交付步骤

1. 对比主窗口内、跨窗口边缘及另一显示器的输入，建立能失败的鼠标消息回归。
2. 修复普通弹窗误入原生拖动处理的问题；区分外部窗口夺走捕获与内部窗口交接，补对应对照测试。
3. 完整编译产品，运行相关窗口、停靠与公开仓检查；独立复核变化。
4. 用隔离数据库和合成音频检验扫描前、中、后的实际包，保存包身份与真实截图。
5. 检查与最新 QA 合并后的结果，按批准的交付安排通过 PR 合入 QA；实际鼠标点击、拖动释放和跨屏体验经用户明确确认后，完成卡片收尾。

实现和可重复检查已完成；实际包的输入消息与隔离扫描已验证，物理鼠标操作体验仍待用户确认。最新验收状态、包身份和后续结果以对应开发卡为准。

## 修复设计

扫描文件夹等弹窗移出主窗口后，会成为独立的 ImGui Win32 窗口。普通弹窗没有停靠模块 ID，不能因为空 ID 相等就拦截它的鼠标松开消息。原生标题栏拖动结束后残留的窗口句柄也不能拦截后续控件点击。

外部窗口取得鼠标捕获时，Windows 可能不再向原窗口发送鼠标松开消息。此时外置窗口通过现有的 `ReleaseImGuiLeftButtonOnCaptureLoss()` 清除 ImGui 左键按下状态。同一 ImGui 上下文内的捕获转移继续保持按下；捕获暂时变空也不主动清除，因为后端销毁外置窗口时会先释放捕获、再交给主窗口等待真实松开。

本修复只调整共用窗口消息分派，不更改扫描逻辑、窗口布局或停靠规则。只有正在进行且归属匹配的原生标题栏拖动才拦截客户区输入。

## 自动回归

在 Windows 的 VS2022 x64 开发环境运行：

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Debug --target HarkenSearch TestDetachedViewportInput TestDockNativeCaptionBridge TestDockDragSession TestDockLayoutTree TestDockHitTest TestViewportGlLifecycle --parallel 4
ctest --test-dir build -C Debug --output-on-failure -R "^(DetachedViewportInput|DockNativeCaptionBridge|DockDragSession|DockLayoutTree|DockHitTest|ViewportGlLifecycle|TestImguiDockingViewportContract)$"
python tools/run_public_checks.py
```

`TestDetachedViewportInput` 使用隐藏的真实 Win32 窗口、产品共用消息分派及真实 ImGui Win32 后端，不移动系统鼠标。覆盖：

- 主窗口对照、普通外置弹窗、连续点击和负坐标。
- 停靠功能窗的普通控件，以及标题栏拖动结束后的控件点击。
- 其他模块正在拖动时，普通弹窗仍能收到松开消息。
- 使用真实 `SetCapture` 将捕获交给外部窗口，不发送 `WM_LBUTTONUP`，验证普通弹窗与功能窗能解除按下状态，且下一次点击可用。
- 直接交给主窗口，以及先释放再交给主窗口，两种内部接续都保持按下，直到真正收到松开消息。
- 原生标题栏拖动的开始、释放及捕获中断。

普通点击同时检查按下态、松开后的状态和原消息处理函数的实际接收次数。捕获中断检查没有伪造松开消息；每项结果记录后才清理状态，避免前一项失败污染后一项。该测试已接入 Windows CI。

## 实际包验收

使用隔离配置与新建测试数据库，不使用现有资料库。记录包的 SHA256、系统缩放比例和各显示器位置；负坐标与不同缩放比例应分别记录是否实测。

| 场景 | 操作 | 应有结果 |
| --- | --- | --- |
| 扫描前 | 在主窗口内、跨主窗口边缘和另一显示器上反复点击扫描选项 | 每次点击仅触发一次，下一次点击正常 |
| 拖动 | 将扫描窗口拖过主窗口边缘及显示器边界，再松开 | 窗口立即停止跟随鼠标，按钮可继续使用 |
| 扫描中 | 导入合成 WAV 测试目录，移动扫描窗口并操作可用按钮 | 扫描进度继续，拖动和按钮有响应 |
| 完成或取消后 | 重新打开扫描窗口，再拖动和点击 | 不残留按下或拖动状态 |
| 捕获中断 | 在拖动过程中切换窗口，松开后返回 | 不持续拖动，下一次点击有效 |
| 同根因功能窗 | 对独立的筛选等功能窗重复拖动与控件操作 | 标题栏与客户区均正常 |

消息注入只能证明消息传递和输入状态，不能代替实际按钮命中、鼠标拖动、混合缩放或操作流畅度的体验验收。截图需来自同一待验包，用户确认前不得标为前端验收通过。
